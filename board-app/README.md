# HomeVIS 보드 화면 (Flutter)

LG ATLAS OS 보드(Raspberry Pi 5)에 설치하는 HomeVIS 대시보드입니다.
보드에는 브라우저가 없어서, 웹 대시보드(React v5, 저장소 루트의 `src/`)를 Flutter 로 그대로 옮겼습니다.
같은 백엔드(HomeVIS-Backend v0.8.x) API · WebSocket 을 쓰고, 화면 구성 · 문구 · 색도 웹과 같습니다.

- 앱 이름 `homevis_gui`, 앱 ID `com.atlas.app.homevis_gui`, 설명 "HomeVIS dashboard"
- Flutter **3.27.4** 고정 (보드 엔진 버전). `pubspec.yaml` 이 다른 버전을 막습니다
- 순수 Dart 패키지만 사용: `http`, `web_socket_channel`, `provider`, `lucide_icons` (네이티브 코드가 있는 패키지 없음)
- 글꼴 Pretendard 를 앱에 넣었습니다 (`assets/fonts`, SIL OFL 1.1 — `assets/fonts/OFL.txt`). 실행 중 내려받는 것 없음
- 터치 · 마우스만 가정합니다 (키보드 입력 화면 없음). 누르는 곳은 48×48 이상
- 설정(화면 모드 · 권한 동의 · 테마 · 글자 크기)은 보드에서 유일하게 쓸 수 있는 `$HOME` 아래 `$HOME/.config/homevis_gui/prefs.json` 에 저장합니다 (아래 "설정 저장")

## 화면

왼쪽 레일(홈 · 주방 · 욕실 · 기록 · 설정) + 상단(날짜 · 제목 · 날씨 · 시계) + 상태 배너. 탭 전환만 있고 라우팅은 없습니다.
기준 화면은 1280×720 이고, 더 작으면 배치를 유지한 채 비율대로 줄이고(예: 1024×600), 더 크면 칸이 넓어집니다.

| 화면 | 일반 모드 | 어르신 모드 |
| --- | --- | --- |
| 홈 | 집 상태 카드(주방 · 욕실 · 보호자) + 지금 위치 평면도(주방 \| 침실 \| 욕실, 위치 점 · 신뢰도 · 전구 켜고 끄기) + 기기 카드 5개 | 상태 한 줄 + 큰 타일 4개 |
| 위치 크게 보기 | 재실 감지: 공간별 신뢰도 · 행동 · 최근 1분 그래프 · 센서 노드 신호(2.5초마다) · 실시간/갱신 멈춤 + 조명 밝기 · 환풍기 풍량 · 공기청정기 | 공간별 큰 스위치 |
| 주방 | 인덕션(조회 전용, 큰 온도 · 최근 3분 그래프 · 과열선) · 재실 · 정수기 · 환풍기 · 이번 조리 \| 주방 기록 | 인덕션 · 재실 큰 타일 |
| 욕실 | 상태 패널 · 조명/환풍기/재실 타일 · 낙상 대응 단계 · 욕실 기록 | 큰 글씨 상태 · 타일 |
| 기록 | 날짜별 묶음 · 분류(전체/화재 예방/낙상/생활 자동화) · 공간 · 기간(오늘/7일/30일) · 쪽 넘김 · 상세 · 피드백 · 최근 7일 | 같은 화면, 큰 글씨 · 쪽당 3~4건 |
| 설정 | 화면(테마 · 화면 모드) · 비상 연락처(키패드 등록 · 변경) · 앱 권한 · 음성 · 정보 | + 글자 크기 100~130% |

시트 · 알림: 기기 상세(전등 밝기 단계 0/20/100, 환풍기 약/중/강, 공기청정기 전원 · 자동/수동 · PM2.5/PM10/등급, 인덕션 · 정수기 정보, 끊긴 기기 다시 연결),
날씨(비 소식 한 줄 · 시간대별 · 체감/습도/강수), 낙상 경보(서버가 실제로 한 일만: 문자 보냄 / 본인 응답 대기 카운트다운 / 못 보냄),
안전 조치 안내(피드백), AI 안내 토스트, 기기 제어 실패 토스트, 음성 명령 패널(레일 아래 마이크 버튼).

조명은 기기 ID 가 아니라 공간(room)으로 묶습니다. 백엔드 v0.8 의 주방 전등 `light-02`(room `kitchen`)는
홈 평면도 주방 칸 전구 · 위치 크게 보기 주방 칸 밝기 슬라이더(어르신: 큰 스위치) · 주방 화면 조명 타일(어르신: 큰 타일)에 나옵니다.

## 첫 실행

1. **화면 모드 선택** — "어떤 화면이 편하세요?" 크게 보기(어르신) / 기본 보기(일반). 고르면 저장되고, 다음부터는 바로 홈. 설정 > 화면 > 화면 모드에서 바꿉니다
2. **권한 동의 창** — 재실 감지(필수, Wi-Fi 신호 · 카메라 없음) · 마이크(보드 음성 명령, 인식 방식에 따라 음성이 외부 서버로 갈 수 있음) · 음성 안내(위험 알림 읽어 주기) · 연락처(낙상 시 보호자 문자).
   답하기 전에는 닫히지 않습니다. **허용** = 음성 명령 + 음성 안내 켜짐(호출어는 꺼진 채), **허용 안 함** = 음성 명령 꺼짐. 설정 > 앱 권한에서 하나씩 바꿉니다
3. 낙상 경보 · 안전 조치 안내는 동의 창보다 위에 뜹니다

키오스크 · 시험용으로 `--dart-define=SKIP_ONBOARDING=true` 를 주면 두 화면을 건너뜁니다 (저장된 값은 바꾸지 않음).

## 설정 저장

- 위치: `$HOME/.config/homevis_gui/prefs.json` (폴더가 없으면 만듭니다). 보드는 파일 시스템이 읽기 전용이고 `$HOME` 만 쓸 수 있습니다
- 저장하는 것: 모드 선택 여부 · 화면 모드 · 동의 여부 · 음성 명령 · 음성 안내 · 테마 · 글자 크기 (작은 JSON, 키 · 개인정보 없음)
- 임시 파일에 쓴 뒤 이름을 바꿔 반쯤 쓴 파일이 남지 않게 합니다
- 파일이 깨졌거나 모르는 값이면 처음 값으로 시작하고, 쓸 수 없으면(권한 · 디스크) 오류 없이 메모리에서 계속합니다
- 저장된 모드가 없을 때의 처음 값은 `DEFAULT_MODE`
- 웹 빌드는 저장하지 않습니다 (메모리만, 켤 때마다 첫 실행 화면)
- 첫 실행부터 다시 보려면 이 파일을 지웁니다 (macOS 앱으로 실행하면 Mac 의 같은 경로에 생깁니다)
- 연락처는 이 파일이 아니라 백엔드에 저장됩니다. 호출어 켜기/끄기도 보드 음성 서비스(백엔드) 설정입니다

## 비상 연락처 등록 (키보드 없이)

설정 > 비상 연락처의 보호자 · 본인 줄에서 **등록 / 변경**, 또는 홈의 "보호자 · 등록 필요"(어르신: 보호자 타일)를 누르면 바로 열립니다.

1. 보호자는 관계를 고릅니다: 보호자 · 아들 · 딸 · 배우자 · 손주 · 이웃 — 고른 말이 이름(`name`)으로 저장됩니다. 본인은 이름이 "본인"으로 고정
2. 큰 숫자 키패드(0~9 · 지우기 · 전체 지우기, 어르신은 더 큼)로 번호를 누릅니다. `010` 이 미리 들어 있고 `010-1234-5678` 로 바로 묶어 보여줍니다
3. 백엔드와 같은 규칙(숫자만 9~11자리, 0 으로 시작)으로 확인한 뒤 `PUT /api/v1/guardian` 또는 `/api/v1/user` `{ name, phone }`
4. 결과: 확인 문자를 보냈으면 "저장했어요. 확인 문자를 보냈어요.", 아니면 "저장했어요. (확인 문자는 보내지 않았어요)". 실패하면 시트에 짧게 알리고 그대로 둡니다
5. 저장 뒤 화면에는 가운데를 가린 번호(`010-****-5678`)만 보입니다 (공용 화면). 변경할 때도 번호는 `010` 부터 새로 누릅니다

> **비용 주의**: 백엔드에 SMS(솔라피) 키가 설정돼 있으면 저장할 때마다 확인 문자가 실제로 발송됩니다(문자 요금). 시험할 때는 SMS 키를 비운 백엔드에서 하세요.

```

  data/                  백엔드 연동: home_source(REST · WS · 폴링) · voice_api(음성 경로 모음) · parse(응답 검사) · translator(기기 · 실시간 메시지 변환)
  models/types.dart      화면 도메인 타입
  store/                 화면 상태(리듀서) · 설정(+ prefs.json 저장소) · 토스트 · TTS 연결 지점(Speaker)

  ui/                    공용 부품 (타일 · 목록 · 세그먼트 · 스위치 · 시트 · 밝기 슬라이더 · 그래프)

```

## 설정 값 (`--dart-define`)

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `API_BASE` | `http://127.0.0.1:8000` | 백엔드 주소. REST 는 `/api/v1`, 실시간은 `ws://…/api/v1/stream` |
| `DEFAULT_MODE` | `normal` | `normal` 또는 `elderly`. 저장된 화면 모드가 없을 때의 처음 값 |
| `SKIP_ONBOARDING` | `false` | `true` 면 첫 실행 화면(모드 선택 · 권한 동의)을 건너뜀 (키오스크 · 시험용) |
| `CANVAS_SCALE` | `0` (자동) | 1920×1080 모니터에서 1280×720 배치를 크게 보이려면 `1.5` |

키 · 토큰 · 비밀번호는 넣지 않습니다. 보드 IP 같은 주소도 코드에 적지 않습니다.

## Mac 에서 실행

Flutter 3.27.4 를 설치한 뒤 (`flutter --version` 으로 확인):

```bash
cd board-app
flutter pub get
flutter analyze
flutter test
```

**macOS 앱** (Xcode 필요): 백엔드를 같은 Mac 에서 띄우고

```bash
flutter run -d macos --dart-define=API_BASE=http://127.0.0.1:8000
```

**Chrome**: 백엔드에 CORS 설정이 없어 브라우저가 다른 출처 요청을 막습니다.
웹 빌드를 백엔드와 같은 출처로 띄우는 프록시가 필요합니다 (예: 정적 파일은 `build/web`, `/api` 는 `http://127.0.0.1:8000` 으로 넘기고 WebSocket 도 허용).

```bash
flutter build web --release --no-web-resources-cdn --dart-define=API_BASE=http://127.0.0.1:<프록시 포트>
# build/web 을 프록시로 띄운 뒤 http://127.0.0.1:<프록시 포트>/ 접속
```

## 보드에 올리기 (LG 개발 컨테이너에서)

LG 가 배포한 Docker 개발 컨테이너 안의 `flutter-atlas` CLI 로 진행합니다. 자세한 옵션은 LG 의 Flutter CLI 가이드를 따릅니다.

1. 컨테이너 안에서 이 폴더로 이동해 ATLAS 플랫폼 폴더를 만듭니다 (`atlas/` 가 생깁니다)
   ```bash
   cd board-app
   flutter-atlas create --platforms atlas .
   ```
2. 생성된 `appinfo.json` 을 확인합니다: 앱 ID `com.atlas.app.homevis_gui`, 설명 `HomeVIS dashboard`, 전체화면 실행.
   보드의 음성 서비스가 앱 권한을 요구하면 생성된 `atlas/meta/appinfo.json` 에 `perm_voice_intent` 를 추가해야 할 수 있습니다 (정확한 위치 · 형식은 LG 가이드 확인)
3. 릴리스 IPK 빌드 (백엔드가 보드 안 Docker 에서 돌면 주소는 127.0.0.1)
   ```bash
   flutter-atlas build atlas --ipk --release --dart-define=API_BASE=http://127.0.0.1:8000
   # 어르신 모드로 시작: --dart-define=DEFAULT_MODE=elderly
   # 1920×1080 모니터: --dart-define=CANVAS_SCALE=1.5
   ```
   결과물은 `build/atlas/arm64/release/ipk/` 아래에 생깁니다
4. 연결만 먼저 확인하려면 건강 확인 앱을 같은 방법으로 빌드합니다 (앱 ID 가 같으니 하나씩 설치)
   ```bash
   flutter-atlas build atlas --ipk --release -t lib/main_health.dart --dart-define=API_BASE=http://127.0.0.1:8000
   ```
5. 보드(`<보드 IP>`)를 기기로 등록한 뒤 `flutter-atlas install -d <기기 ID>` 로 설치하거나,
   가이드의 직접 설치 절차(IPK 를 `<보드 IP>` 로 복사 → `opkg` 설치 → `appinfo.json` 의 실행 명령)로 설치합니다

`atlas/` 폴더는 컨테이너에서 만들어지므로 이 저장소에는 아직 없습니다. 만든 뒤 커밋할지는 팀에서 정합니다.

## 동작 메모

- 처음 불러오기에 실패하면 "서버에 연결하지 못했어요 + 다시 시도" (보드 부팅 직후 백엔드가 늦게 뜨는 경우)
- WebSocket 이 끊기면 1초부터 10초까지 늘려 가며 다시 연결하고, 놓친 안전 이벤트는 `?since=<마지막 이벤트 id>` 로 받습니다
- 기기 온라인 상태는 `GET /devices` 를 15초마다 확인합니다
- 기기 제어 결과는 WebSocket `device.state` 로만 반영합니다. 밝기 슬라이더만 보낸 값을 최대 5초 먼저 보여줍니다 (웹과 같음)
- 서버 응답은 그대로 믿지 않습니다. 빠지거나 모르는 값은 기본값으로 두고, 이상한 메시지는 버립니다 (테스트 포함)

## 음성 (보드 마이크)

보드에 붙은 마이크의 녹음 · 음성 인식은 **백엔드(보드 음성 서비스)가 맡고**, 화면은 시작 · 취소만 보내고 진행 상황을 보여줍니다.
아래 중 **보드 마이크 부분은 제안 계약**입니다 (백엔드 v0.8 에는 아직 없음). 경로는 `lib/data/voice_api.dart` 의 `VoicePaths` 한곳에 모았으니 이름이 바뀌면 거기만 고치면 됩니다.

| 방향 | 요청 · 이벤트 | 내용 |
| --- | --- | --- |
| 화면 → 서버 | `POST /api/v1/voice/listen` `{}` | 마이크 버튼. `202 { voiceId }`. `409` = 이미 듣는 중 → 패널만 연다 (본문에 `voiceId` 가 있으면 사용) |
| 화면 → 서버 | `POST /api/v1/voice/listen/cancel` `{ voiceId }` | 듣는 중에 패널을 닫거나 버튼을 다시 누를 때. 오류는 무시 |
| 서버 → 화면 | WS `voice.status` | `status`: `listening`(듣는 중) → `recognizing`(알아듣는 중, `text` 가 있으면 함께) → 기존 `received` · `thinking` · `confirm_required` · `executed` · `answered` · `cancelled` · `timeout` · `failed`. `source`: `button` · `wakeword`. `failed` 의 `reason`: `mic_unavailable`(마이크를 찾을 수 없어요) · `no_speech`(말씀이 들리지 않았어요), 그 밖은 "지금은 음성 명령을 쓸 수 없어요" |
| 화면 ↔ 서버 | `GET /api/v1/voice/settings` → `{ wakeWord, standby }` | 앱 시작 · 설정 > 음성을 열 때 읽음 |
| 화면 → 서버 | `PUT /api/v1/voice/settings` `{ wakeWord }` → `{ wakeWord, standby }` | 호출어("홈비스")로 부르기. 기본 꺼짐 |
| 서버 → 화면 | WS `voice.settings` `{ wakeWord, standby }` | `standby: true` 면 레일 마이크 버튼에 주황 점 + "호출어 대기" (음성 명령을 꺼 두었어도 표시) |
| 화면 → 서버 | `POST /api/v1/voice/commands/{voiceId}/confirm` `{ approved }` | (기존) `409` = 다른 화면이 이미 답함 → 오류 없이 확인 창만 닫음 |

- `voice.status` 가 오면(호출어로 시작한 것 포함) 패널이 저절로 열립니다. 언제나 가장 최근 `voiceId` 하나만 보여주고, 사용자가 닫은 명령의 늦은 상태는 무시합니다
- 서버 소식이 20초 동안 없으면 "잘 듣지 못했어요"로 닫습니다
- **지금 백엔드(엔드포인트 없음)에서도 그대로 동작**: 마이크 버튼은 `404/405` 면 "지금은 음성 명령을 쓸 수 없어요"를 잠깐 보여주고 닫힙니다(자동 재시도 없음). 음성 설정이 없으면 호출어 스위치를 끄고 "보드 음성 연결 후 사용할 수 있어요" 한 줄만 보입니다
- 설정 > 음성: **음성 명령 사용**(끄면 마이크 버튼이 사라지고, 서버 호출어도 끕니다) · **호출어로 부르기 (홈비스)** · **위험 알림 음성 안내**(끄면 `Speaker` 로 가지 않음)
- 다른 장치가 문장을 보낼 때는 기존 `POST /voice/commands` (`VoiceService.send`) 그대로
